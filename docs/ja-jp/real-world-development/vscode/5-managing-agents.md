GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では作業をリアルタイムで確認でき、各ツールの呼び出しやファイルの編集が表示されます。エディター内で差分を確認し、変更ごとに採用または取り消しを選び、追加のプロンプトで作業を調整、拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッション中にエージェントへ指示し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じるユーザーのためにライト モードも用意したいという追加の要望がありました。新しい会話を最初から始める代わりに、既存のセッションに指示を追加します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが行う各手順を確認できます。調査したファイル、実行したコマンド、提案された編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールして各ツールの操作を確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャット内に表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を取り消し、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、セッション中に変更されたすべてのファイルを確認できます。

> [!NOTE]
> ターミナル コマンドの実行など、操作の許可を求めるツール呼び出しがある場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドのみ承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライト モードの追加を指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えも追加します。既存の会話を続けることで、エージェントは前の作業、変更したコンポーネント、スタイル設定の方法、設定を local storage に保存するパターンを把握できます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライト モードの追加を提案します。
3. ハイ コントラストのときと同じように、新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合（たとえば、切り替え UI を意図しない方法でリファクタリングする場合）は、チャット入力欄の隣にある **Stop** ボタンで停止して、明確な追加指示を送信できます。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりも速く調整できます。追加プロンプトで変更を依頼します（「CSS を簡潔にする。セレクターを重複させず CSS 変数を使う」など）。修正を促したり（「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」など）、範囲を拡張したり（「両方の切り替えにキーボード ショートカットも追加する」など）できます。

## 変更されたファイルをレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたすべてのファイルを確認します。Astro コンポーネント、スタイル、関連テストなどが含まれるはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティのパターン（ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存）が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して方向付けました。各ファイルの編集を確認し、採用または取り消しを選択し、コンテキストを保ったまま追加プロンプトを送信して作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- ファイル編集を個別に採用または取り消しました。
- 追加プロンプトを使って進行中のセッションに指示を出しました。
